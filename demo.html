System architecture & ML pipeline
1

Data Collection & Ingestion

73 Canadian destinations across 11 provinces and territories. 500 synthetic user profiles, 5,462 user-destination ratings, 12-month weather records, and supplementary hotel, attraction, and meal tables are loaded from local CSV files.

2

Preprocessing & Feature Engineering

Destination tags are vectorised with TF-IDF. Numeric features such as average daily cost, average rating, and weather-derived visitor index are min-max scaled before being combined into a destination feature matrix.

3

Content-Based Filtering (CBF)

Cosine similarity is computed between a user preference vector built from selected interests and the destination feature matrix. This produces a ranked list of destinations based on profile similarity.

4

Collaborative Filtering (CF)

The collaborative component factorises the user-destination ratings matrix using truncated SVD from SciPy. Existing users receive collaborative scores, while cold-start users fall back to a content-based and popularity-heavy blend.

5

Hybrid Ensemble Score

Final score = 0.45 x CBF score + 0.35 x CF score + 0.20 x popularity score. The popularity term is derived from destination ratings and used as a lightweight prior inside the hybrid model.

6

Constraint Filtering

Recommendations are filtered by optional province, season suitability, and budget tolerance. This keeps the final shortlist aligned with the traveler's declared constraints.

7

Offline Evaluation

The prototype includes offline Precision@K, Recall@K, NDCG@K, and RMSE evaluation on the synthetic interaction dataset. These results should be interpreted as prototype-level offline metrics rather than production benchmarks.

destinations.csv - Core Destination Registry

73 Canadian destinations with id, name, province, coordinates, tags, average daily cost, average rating, seasons, and destination type. This is the main catalogue used by both the content-based and hybrid components.

users.csv - Traveller Profiles (500 users)

Synthetic user profiles capturing age, daily budget, trip duration, home province, interest tags, preferred season, and group composition. These records support the collaborative filtering setup and API demos.

ratings.csv - Interaction Matrix (5,462 events)

Synthetic user-destination rating events with user_id, dest_id, rating, and visit_date. The 500 x 73 interaction matrix is sparse and is factorised by the collaborative filtering model.

weather.csv - Seasonal Climate Profiles

Monthly weather records per destination with average temperature, precipitation, and visitor index. The visitor index is used as a weather-derived numeric feature during recommendation.

hotels.csv and meals.csv - Accommodation & Dining

Hotel and restaurant records linked by destination_id. These tables currently support dataset completeness and future itinerary extensions, but they are not yet part of the live scoring pipeline.

attractions.csv - Points of Interest

Attraction records per destination including name, cost, type, and coordinates. Like the hotel and meal tables, this dataset is available for analysis and possible future itinerary planning work.

Synthetic Data Design Note

The main recommendation datasets in this repository are synthetically generated for academic prototyping. They are inspired by public tourism data structures, but they are not direct copies of external microdata sources.

Hybrid scoring is implemented end-to-end

The codebase combines content-based, collaborative, and popularity signals into a single recommendation score that can be queried through the API and demonstrated in a project presentation.

✓

Cold-start users are handled gracefully

When no collaborative history exists for a user, the recommender falls back to a content-based and popularity-weighted strategy instead of failing to return results.

✓

Evaluation is available inside the prototype

The repository exposes offline Precision@K, Recall@K, NDCG@K, and RMSE calculations for the synthetic interaction dataset, which is suitable for prototype-level reporting.

i

Ratings matrix sparsity remains realistic

500 users x 73 destinations = 36,500 possible interactions. With 5,462 observed ratings, the matrix remains sparse enough to motivate matrix factorisation while still being easy to demonstrate in an academic prototype.
